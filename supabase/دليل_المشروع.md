# نظام متابعة العمليات — دليل المشروع

> **اقرأ هذا الملف أولاً قبل أي تعديل.**
> يشرح بنية النظام، وأماكن الأجزاء في الكود، والأخطاء التي وقعنا فيها سابقاً وكيف نتجنبها.

---

## ما هو النظام

منصة لمكتب تصدير وتخليص. تدير دورة الشحنة كاملة:
**طلب (مهمة) ← إدخال بيانات ← مراجعة واعتماد ← إصدار مستندات ← تحصيل.**

يعمل أونلاين، بيانات مشتركة بين الفريق، صلاحيات مفروضة من قاعدة البيانات.

## الملفات

| الملف | الدور |
|---|---|
| `index.html` | **النظام كله في ملف واحد** (~6 MB) — يُرفع على Netlify |
| `1_قاعدة_البيانات.sql` … `10_نوع_الشحن_للشركة.sql` | ترحيلات قاعدة البيانات — **تُشغَّل بالترتيب** |
| `نسخة-احتياطية-*.json` | نسخ احتياطية من البيانات |

### قاعدة القاعدة: الترتيب ملزم

ملفات SQL تُشغَّل بالترتيب الرقمي في **Supabase → SQL Editor**. كل ملف يعتمد على ما قبله.
كلها **آمنة للتشغيل أكثر من مرة** (تستخدم `if not exists` و `drop policy if exists`).

**خطأ شائع:** تشغيل ملف قبل الذي يسبقه ← رسالة `relation "X" does not exist`. الحل: شغّل الناقص بالترتيب.

### لماذا `data jsonb` في جدول الشحنات

الشحنة فيها ~60 حقلاً وتتغير باستمرار. حفظها في `jsonb` يعني أن **إضافة حقل جديد لا تحتاج ترحيل SQL** — فقط أضف الحقل في الفورم.

الحقول التي تحتاج فهرسة أو قيوداً (`status`, `company_id`, `due_date`, `bol_template_id`) هي أعمدة حقيقية.

## الأدوار والصلاحيات

| الدور | الصلاحية |
|---|---|
| `admin` | كل شيء — يرى كل الشحنات، يدير المستخدمين والشركات والقوائم |
| `editor` | يضيف ويعدّل **شحناته فقط**، ويسجّل التحصيل |
| `staff` | **المهام فقط** — ينشئ الشحنة من مهمة، يرسلها للاعتماد، لا يعتمد |
| `viewer` | قراءة وطباعة فقط |

### الصلاحيات مفروضة من قاعدة البيانات (RLS) وليس من الواجهة

هذه نقطة جوهرية: إخفاء زر في الواجهة **ليس حماية**. الحماية الحقيقية في سياسات Row Level Security.

**اختُبرت فعلياً على PostgreSQL** — الخادم يرفض:
- الموظف يعتمد شحنته بنفسه
- الموظف يعدّل شحنة بعد اعتمادها
- الموظف يرقّي نفسه إلى مدير
- الموظف يسجّل تحصيلاً
- محرر يرى شحنات محرر آخر

**عند إضافة أي جدول جديد:** فعّل RLS واكتب سياساته، وإلا سيكون مكشوفاً.

## دورة حياة الشحنة

```
draft  ──(الموظف يرسل)──►  review  ──(المدير يعتمد)──►  sent
                              │
                              └──(المدير يرجّع + ملاحظة)──►  rework  ──► يعود إلى review
```

- **المدير** يحفظ ← `sent` مباشرة
- **الموظف** يحفظ ← `draft` ثم تفتح شاشة مراجعة إجبارية ← `review`

**لماذا:** أماكن الحقول محفوظة كنِسَب مئوية، والمحرر يفترض A4. لو تُرك الارتفاع حراً ورُفع نموذج بنسبة مختلفة، **يفيض على صفحة ثانية وتظهر البيانات في صفحة بيضاء** — وهذا حدث فعلاً.

### دوال مفتاحية

- **`buildSheet(r, kind)`** — نقطة الدخول لكل المستندات. تغلّف `withCompany` تلقائياً ليأخذ كل مستند بيانات شركته.
- **`withCompany(r, fn)`** — تبدّل `company` مؤقتاً وتعيدها. **استخدمها دائماً** عند بناء مستند لشحنة معيّنة.
- **`fieldPos(docType, def)`** — تُرجع موضع الحقل. تراعي النموذج النشط أثناء التحرير.
- **`fileToScaledDataURL(file, maxDim, opts)`** — تقبل صورة أو PDF. **مرّر `{format:'jpeg'}` للنماذج** (انظر التحذير أدناه).

## أخطاء وقعنا فيها — لا تكررها

### ١) دوال ومعرّفات مكررة ← أخطر مشكلة واجهتنا

عند إضافة ميزة، تحققنا مراراً أنها **موجودة سلفاً** فأضفنا نسخة ثانية. في JavaScript **آخر تعريف يفوز**، فالنسخة القديمة كانت تُلغي الجديدة.

**ما حدث فعلاً:** النظام كان يقرأ من تخزين المتصفح الفارغ بدل الخادم — البيانات موجودة (7 شحنات) والشاشة تعرض صفراً.

**قبل إضافة أي ميزة، شغّل:**

```bash
# دوال مكررة
grep -oP "^\s*(async )?function \K\w+" index.html | sort | uniq -d

# معرّفات HTML مكررة
python3 -c "
import re, collections
s=open('index.html',encoding='utf-8').read()
body=s[s.index('<body>'):s.index('<script>')]
ids=re.findall(r'\bid=\"([\w\-]+)\"', body)
print({k:v for k,v in collections.Counter(ids).items() if v>1} or 'نظيف')"

# معالجات نقر مكررة على نفس الزر
python3 -c "
import re, collections
s=open('index.html',encoding='utf-8').read()
h=re.findall(r\"getElementById\('([\w\-]+)'\)\.addEventListener\('click'\", s)
print({k:v for k,v in collections.Counter(h).items() if v>1} or 'نظيف')"
```

**الثلاثة يجب أن تُرجع "نظيف".**

### ٢) ابتلاع الأخطاء بصمت

`.insert()` في مكتبة Supabase **لا ترمي استثناءً** عند الفشل — تُرجع `{error}`. تجاهله يعني أن العملية تفشل والبرنامج يقول "تم بنجاح".

**دائماً:**
```js
const {data, error} = await sb.from('table').insert(row).select();
if(error) throw error;
```

### ٣) حجم الصور

نموذج A4 محفوظ كـ PNG ≈ **1.15 MB**. عشرة نماذج = 11 MB ← الخادم يرفض برسالة غامضة.

**استخدم JPEG للنماذج** (0.22 MB — أصغر بخمس مرات). **PNG للشعار والختم فقط** لأن الشفافية مطلوبة.

### ٤) العناصر المنقولة

عند إعادة هيكلة الواجهة، بقي كود يشير إلى عناصر حُذفت.

**مثال حقيقي:** فورم الإدخال كان داخل لوحة الشحن البري. عند فتح التبويب البحري كانت اللوحة مخفية والفورم معها — الزر يعمل لكن لا شيء يظهر.

**بعد أي نقل، تحقق:**
```bash
python3 -c "
import re
s=open('index.html',encoding='utf-8').read()
body=s[s.index('<body>'):s.index('<script>')]
print('توازن الوسوم:', len(re.findall(r'<div\b',body)), '/', body.count('</div>'))"
```

### ٥) تضارب عملاء المصادقة

إنشاء أكثر من عميل Supabase بنفس `storageKey` يسبب سلوكاً غير محدد — بعض الطلبات تُرسل بتوكن غير صالح وترجع فارغة.

**الحل المطبّق:** العميل الأساسي بـ `storageKey: 'shipdocs-auth'`، وعميل إضافة المستخدمين بمفتاح منفصل ويُنشأ عند الحاجة فقط.

### ٦) لا تطرد المستخدم بسبب خطأ شبكة

كان فشل جلب الملف الشخصي — ولو لحظة تأخير — يسجّل خروجاً فورياً. كل تحديث للصفحة كان يخرج المستخدم.

**الحل:** ثلاث محاولات، والتفريق بين خطأ الشبكة (نُبقي الجلسة) وغياب الصلاحية فعلاً (نسجّل خروجاً).

## طريقة العمل المُجرَّبة

1. **اقرأ قبل أن تكتب** — تأكد أن الميزة غير موجودة (`grep` على اسم دالة أو معرّف متوقع)
2. **عدّل** — بأصغر تغيير ممكن
3. **تحقق من الصياغة**:
   ```bash
   node -e "const s=require('fs').readFileSync('index.html','utf8');
   const m=s.match(/<script>([\s\S]*)<\/script>/);
   try{ new Function(m[1]); console.log('سليم'); }catch(e){ console.log('خطأ:', e.message); }"
   ```
4. **افحص التكرار** — الأوامر الثلاثة أعلاه
5. **اختبر في متصفح حقيقي** — Playwright، لا افتراضات
6. **اختبر الصلاحيات على PostgreSQL فعلي** إن غيّرت RLS

**القاعدة:** لا تسلّم شيئاً لم تختبره. كل بج في هذا المشروع ظهر لأنه لم يُختبر، لا لأنه صعب.

## أخطاء شائعة وحلولها

| الرسالة | السبب | الحل |
|---|---|---|
| `Could not find the table 'public.X'` | ملف SQL لم يُشغَّل | شغّل الملفات الناقصة بالترتيب |
| `relation "X" does not exist` | ملف SQL شُغّل قبل الذي يسبقه | شغّل السابق أولاً |
| `row-level security policy` | الدور لا يملك الصلاحية | متوقع — تحقق من الدور |
| `payload too large` | صورة كبيرة | استخدم JPEG وقلّل الدقة |
| بيانات في صفحة والنموذج في أخرى | نسبة النموذج ليست A4 | مثبّت الآن — تحقق من `.tpl-wrap` |

**استعلام فحص سريع للجداول:**

```sql
select
  (select count(*) from information_schema.tables where table_name='tasks')            as "المهام",
  (select count(*) from information_schema.tables where table_name='shipment_comments') as "التعليقات",
  (select count(*) from information_schema.tables where table_name='payments')          as "الدفعات",
  (select count(*) from information_schema.tables where table_name='companies')         as "الشركات",
  (select count(*) from information_schema.tables where table_name='clients')           as "العملاء",
  (select count(*) from information_schema.tables where table_name='bol_templates')     as "نماذج_البوالص";
```

الكل يجب أن يكون `1`.

## قبل أي تعديل

**خذ نسخة احتياطية** من: لوحة التحكم ← النسخ الاحتياطي ← تصدير.

**واحتفظ بنسخة من `index.html` الحالي** — للرجوع السريع إن ساء شيء. Netlify يحتفظ أيضاً بكل النسخ المرفوعة (تبويب Deploys).

## معلق / لم يُنفَّذ بعد

- **البوليصة البحرية** — لم يُرفع نموذجها بعد
- **الربط مع المنصة الحكومية** — يحتاج API من جهتهم؛ إطار العمل داخل المتصفح محجوب أمنياً (`X-Frame-Options`)
- أفكار مؤجلة: تكاليف وربحية الشحنة، بوابة للعملاء، أرشيف المستندات الموقّعة

## ملاحظة على أسلوب صاحب المشروع

يفضّل **البساطة مع الشمول**. يلاحظ التفاصيل الدقيقة (اختلاف خط، تنسيق طباعة، ترتيب حقل) ويصفها بوضوح — ملاحظاته دقيقة وتستحق التنفيذ الحرفي.

يعمل بالعربية. الواجهة كلها RTL. **حافظ على ذلك.**
